# List 和 Map 线程安全

- List 和 Map 都有一个不常见的线程安全实现。
    
- 因为线程安全，所以效率比较慢，变得不常见。
    

---

# ArrayList（数组列表）

1. 从 1 开始算的话，寻址公式需要 `(i - 1) * 存储数据的类型大小`，增加一个指令，相对从 0 开始的那个性能会低一些。
    
2. 查询快，增删慢；链表相反。
    
3. 成员变量（属于类的里面），而静态变量也属于成员变量的一种。
    
4. 创建：
    
    - 有初始容量的话，就是多大初始，有多大容量。
        
    - 没有的话，根据默认值创建 10 大小的数组（懒加载）。
        
5. 扩容的时候：`new = old + old >> 1`。
    
    - 好处：折中，位运算更快（右移相当于 `/2`），然后拷贝。
        
6. 底层实现：
    
    1. 数组
        
    2. 初始 0，添加后为 10
        
    3. 扩容为 1.5 倍
        
    4. 添加：先计算，够的话直接添加，不够再扩容，返回布尔
        
7. 数据和 List 之间的转化：
    
    - 工具类的 `asList`（指针引用）
        
    - `toArray`（新对象）
        

---

# LinkedList

## 区别

1. 数据结构：动态数组 / 双向链表
    
2. 操作数据效率：查询、新增、删除
    
3. 空间占用
    
4. 线程安全：都不安全；想保证的话（局部变量）（`synchronized` 包装）
    

- ArrayList 需要扩容 1.5 倍（神秘），LinkedList 不需要。

# HashMap

## 实现原理

1. 散列表（哈希表）：数组 + 链表 / 红黑树
    
2. key 相同，覆盖原始。
    
3. key 不同（哈希冲突），放入链表或者红黑树（长度大于 8，长度大于 64）。
    
4. 获取时候，计算 hash，判断 key 是否相同。
    

- JDK 1.8 之前：没有红黑树。
    
- JDK 1.8 之后：有红黑树，然后扩容后，红黑树节点小于等于 6 个的话，退化成链表。
    

## put 方法的具体流程

1. 懒加载，0.75 是时间空间最合适的权重（冲突多了查询慢）。
    
2. 判断是否初始化（初始化）。
    
3. 然后 `%` 数组长度（计算 hash 索引）。
    
4. 没有的话，直接新增（添加）。
    
5. 新增的时候考虑是否大于 0.75，准备扩容。
    
6. 然后新增的位置已经有数据的话，就要判断 key 是否一样，一样就覆盖。
    
7. 是红黑树还是链表：
    
    - 链表的话判断 key 是否存在，存在覆盖，不存在再判断是否大于等于 8。
        
    - （链表和红黑树都需要判断是否重复 key）
        

## HashMap 扩容

- 初始化：懒加载 16
    

1. 变长一倍
    
2. 新建
    
3. 遍历旧的：
    
    1. 只有一个
        
    2. 红黑树
        
    3. 链表
        
    
    - 算变化：
        
        - 无变化：原位置
            
        - 有变化：+ 老的长度
            

## HashMap 的寻址算法

1. `>>>` 让 hash 值更加均匀，减少 hash 冲突（高位的数下来融合）。
    
2. `(n - 1) & Hash` 效率高，就不用取模了。
    
    - 原理：保留 hash 的低 k 位，其他位清零。
        

## HashMap 的数组长度一定是 2 的次幂

1. 计算索引效率更高。
    
2. 扩容的时候计算新的索引。
    

## HashMap 多线程死循环

- JDK 1.7 之前，用的是头插法（新来的在头上，很反直觉）。
    
- 关键词：`e`、`next`
    
- 两个线程的 `e` 和 `next` 来回绕，最终 `b -> a`，然后新来的 `a` 覆盖 `a`，导致 `b` 被 `a` 指向的同时又指向了 `a`。
