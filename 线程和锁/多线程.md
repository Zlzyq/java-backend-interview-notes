	## 线程和进程的 区别

1. 进程是正在进行的程序实例 包含一个或多个线程 每个线程执行不同的任务
    
2. 不同的进程 用不同的空间 但是 同一进程的线程共享空间
    
3. 线程 更轻 上下文切换 成本低一些
    

## 并行和并发的区别

- **并发**：同一时间 轮流做多个事情 多个线程轮流使用一个或多个cpu
    
- **并行**：同一时间 同时做多件事情 4个cpu同时执行4个线程

## runnable 和 Callable有啥区别

| 对比维度     | **Runnable**                    | **Callable**(比较新)                  |
| -------- | ------------------------------- | ---------------------------------- |
| **返回值**  | 没有（`void run()`）                | **有**（`V call() throws Exception`） |
| **抛异常**  | **不能**抛出受检异常（Checked Exception） | **可以**抛出异常，交给上层处理                  |
| **引入版本** | Java 1.0（老古董）                   | Java 1.5（配合并发包引入）                  |
| **核心作用** | 仅仅是执行一个任务                       | 执行任务并**获取执行结果**（配合Future）          |

## run 和 start（）有什么区别

run方法是要被线程执行的代码 可以被多次调用  
然后start 是开启一个线程 执行run方法 中的逻辑代码 start方法只能被调用一次

## 线程的状态 是怎么变化的

| 状态              | 含义       | 如何进入                                            | 如何离开                                  |
| --------------- | -------- | ----------------------------------------------- | ------------------------------------- |
| `NEW`           | 已创建未启动   | `new Thread()`                                  | 调用 `start()` → `RUNNABLE`             |
| `RUNNABLE`      | 可运行/正在运行 | `start()`、被唤醒、获得锁                               | 被阻塞、等待、结束                             |
| `BLOCKED`       | 等待监视器锁   | 竞争 `synchronized` 锁失败                           | 获得锁 → `RUNNABLE`                      |
| `WAITING`       | 无限期等待    | `Object.wait()`、`join()`、`LockSupport.park()`   | `notify/notifyAll`、目标线程结束、`unpark`、中断 |
| `TIMED_WAITING` | 限时等待     | `sleep(ms)`、`wait(ms)`、`join(ms)`、`parkNanos()` | 超时、通知、中断、`unpark`                     |
| `TERMINATED`    | 已终止      | `run()`结束或异常退出                                  | 不可再变                                  |

new 新建的时候 然后运行 销毁 或者等待锁 无限期等待 有限等待

## JMM(Java内存模型)

1. 定义多线程 之间得共享内存 得读写操作得行为规范
    
2. JMM把内存分为两块 一个 是 线程私有 一个 是 所有线程共享内存
    
3. 线程之间相互隔离 通过主内存 进行交互

## 导致并发程序出现问题的根本原因

1. 原子性：完整的操作 可以用 sycn 或者 lock
    
2. 可见性：线程修改共享变量 另一个线程也能看见 volatile
    
3. 有序性：JIT 编译class文件时候重排 cpu执行代码时候重排 volatile
    

## 线程池

## 线程池的核心参数

- 核心线程数目
    
- 最大线程数目 = 核心线程数目 + 救急线程的最大数目
    
- 生存时间 （释放救济线程）
    
- 时间单位
    
- 阻塞队列 核心线程满了进入 这里 这里满了 产生救急线程（FIFO）
    
- 线程工厂 （定制 名字 是否为守护线程）
    
- 拒绝策略 （全部都满了）默认是 抛出异常
    

## 执行原理

核心线程数目 阻塞队列 最大线程数目 拒绝策略

## 如何确定核心线程数

n是cpu核数

- IO密集型任务 2n+1
    
- CPU密集型任务 n+1 (避免切换 然后 减少线程数)
    

## 线程池的种类

1. **创建使用固定线程数的线程池** 没有临时线程 最大容量默认MAX_VALUE 适合知道消耗多少时间的 需要多少个线程
    
2. **单线程 只有一个线程** 没有临时线程 最大容量默认MAX_VALUE  
    需要按照顺序执行的任务
    
3. **可缓线程池** 全都是核心线程执行 任务数密集 执行时间短
